CoreSimulator: local primary evidence

Captured from Apple Xcode 26.6, build 17F113.

simctl identifies the backend capability

“Command line utility to control the Simulator”

“boot — Boot a device or device pair.”

“install — Install an app on a device.”

“launch — Launch an application by identifier on a device.”

“terminate — Terminate an application by identifier on a device.”

simctl install <device> <path>
simctl launch <device> <app bundle identifier>

Source: Apple’s xcrun simctl help, help install, and help launch.

The device can be controlled without Simulator.app’s window

“io — Set up a device IO operation.”

“recordVideo … Records the display to a QuickTime movie.”

“screenshot … Saves a screenshot as a PNG.”

Source: Apple’s xcrun simctl help io.

Simulator.app is a macOS client

Apple’s Simulator executable is an arm64 macOS Mach-O. Its recorded dynamic dependencies include:

/Library/Developer/PrivateFrameworks/CoreSimulator.framework/…/CoreSimulator
@rpath/SimulatorKit.framework/…/SimulatorKit
/System/Library/Frameworks/AppKit.framework/…/AppKit

Source: file and otool -L applied to Xcode’s unmodified Simulator.app/Contents/MacOS/Simulator.

Simulator and device apps are different build targets

Apple’s Xcode 26.6 SDK metadata records:

SDKPlatform IDTarget environmentArchitectures
iphonesimulator26.57simulatorarm64, x86_64
iphoneos26.52nonearm64e, arm64

The shared arm64 instruction set does not make the two build platforms interchangeable.

Source: Apple’s unmodified iPhoneSimulator.sdk/SDKSettings.json and iPhoneOS.sdk/SDKSettings.json.
